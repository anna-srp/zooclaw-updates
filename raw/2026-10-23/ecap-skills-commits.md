### PR Body

默认 Managed Agents 环境已经预装 `playwright-core` 和配套 Chromium，但 PDF 加载器只识别完整 `playwright`，导致标准 CREATE 流程报依赖缺失。原 `fix` 会尝试向 skill 目录安装，并使用 Chromium 安装器不支持的 `--silent`、隐藏错误，业务 Agent 随后改用临时渲染脚本。

本 PR 让检查与渲染使用同一个加载器，选用可启动的匹配浏览器，失败时保留原因；文档任务不再自动安装 Playwright/浏览器/字体或调用 sudo。Python 原有 `uv run --with` 行为保留。

`make.sh check` 会显示选中的模块和浏览器路径，用于核对实际依赖配对。这是显式诊断输出，不包含凭证、不写入 PDF；该命令输出由诊断 JSON 和可读检查结果组成，并以退出码表示成功与否。

## 行为对比

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 环境仅预装可用的 playwright-core | renderer exit 2：`playwright not found` | 通过 NODE_PATH 找到 core，启动其匹配 Chromium，renderer exit 0 |
| 本地残留安装缺少浏览器 | 本地依赖遮蔽共享安装，进入安装恢复 | 继续尝试其他候选；兼容完整 playwright 和全局安装 |
| 依赖检查 | 模块可导入或 CLI 有版本就可能通过，与实际渲染不一致 | 与渲染共用加载器，实际启动并关闭浏览器 |
| 依赖或权限不足 | 隐式 npm/npx 安装；错误被隐藏；字体脚本可能 sudo | `fix` 仅诊断；错误带原因；字体显式准备且不提权 |
| skill 目录 | 安装和 Python 字节码可能写入 | 不在 skill 目录安装或写字节码；真实测试前后文件 hash 一致 |
| 同会话修改 PDF | 观测到继续编辑备用脚本 | 更新保存的内容，复用标准 `make.sh run` |

另修复本地 HTML 文件路径含空格或 `#` 时的 file URL 转义；新增 PDF 回归并注册到现有 Skill Tests 工作流。

**这是单次观测，不是受控性能 A/B，不能把耗时差全部归因于修复。** 旧流程包含依赖恢复、备用脚本和视觉调用；新流程没有调用视觉模型，因此没有验证视觉模型成功/429 延迟。总耗时使用客户端同一时钟，工具区间使用服务端同源事件；工具外时间包含模型、调度和传输。

修复后的实际 `make.sh run` 进程耗时为新建 **5.584 秒**、改稿 **3.411 秒**，均 exit 0。另在同一诊断沙箱对照旧/新 renderer：旧版明确报错，新版真实浏览器生成成功；首次独立封面探针 9.564 秒，随后简短中文 CREATE 2.689 秒，预热及内容不同，不作为平均性能。
