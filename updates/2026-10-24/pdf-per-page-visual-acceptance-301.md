# 修复：生成 PDF 时逐页做视觉验收、发布前校验文件哈希，内容不再编造来源里没有的署名和状态

## 核心宣传点

以前让 Agent 生成 PDF，交付消息常常写着「已核验」，实际上只检查了文字内容：视觉检查工具一旦超时或报错就不再补看页面，改稿重新生成之后也会漏看新增的页；发布时还不比对文件哈希，最后发给你的文件不一定就是检查过的那一份。内容上也会出现编造——把来源里没有的署名、负责人或项目状态写进文档，改稿之后旧状态还残留在新叙述里。

现在这些都由脚本强制执行。每次生成或改写 PDF 之后都会渲染全部页面图并逐页做视觉检查（单次最多 20 页，失败的调用不重发而是改为逐页读图），检查项里新增了「与背景对比不足的文字」这类问题，比如深色底上的灰色表头。渲染前会先算出 PDF 的 sha256 并记录下来，失败时不写哈希文件，所以没检查过的文件不可能被判为通过；发布前哈希校验必须通过，交付消息里也会写清楚检查方式、检查了多少页（n/N）以及过程中出现过的所有工具失败。

内容保真方面收紧为几条硬规则：每一项内容都要能追溯到来源，人名只对应来源里和他直接关联的那一项，改稿后必须搜索被替换掉的旧值。另外还顺带修了排版细节——表格列宽按比例归一化（输入无效时等宽）、没有标题的图表只显示 "Figure N"、封面的 meta 行不再出现多余分隔符、通栏封面副标题的对比度不低于 4.5:1。

实测对比线上版本：三道测试题合计 token 从 111.9 万降到 66.9 万（−40%），端到端耗时 889s → 706s（−21%）；本版本三个回合都在最后一次写入后通过哈希校验再发布，线上版本三个回合则都没有做哈希校验。

## 问题
线上版本交付 PDF 时：
- 只做了文本检查，交付消息却写“已核验”；视觉工具失败后不再看页面，重建后会漏看页面。

## 改动
- **由脚本强制视觉验收**：CREATE 用 `make.sh run --pages-dir DIR`，其他路线用新增的 `make.sh
pages <pdf>`。
  - 两者都渲染全部页图，并在渲染前计算 PDF 的 sha256，写入 `rendered.sha256`。
  - 失败分支不留哈希文件，所以 `-c` 不会对没检查过的文件报 OK。页图渲染失败时以 4 退出，并提示视觉验收未完成。
- **Next 提示给出每次渲染后的规则**：
  - 用视觉工具检查全部页，每次调用最多 20 页（20 页以内只调用一次）；
  - 失败的调用不重发，改为逐页读页图；
  - 对照缺陷清单检查，清单里新增了“与背景对比不足的文字”，例如深色底上的表头；
  - 之后再有写入，就重新运行 `make.sh pages`；
  - 发布前 `-c` 必须报 OK；
  - 交付消息要写检查方式、n/N 以及所有工具失败。
- **SKILL.md**（12,425 字节，#299 是 10,953）：
- Delivery acceptance 精简为 5 行，Content fidelity 精简为 4
行：每项内容都能追溯到来源；人只对应来源里和他关联的那一项；改稿后搜索被替换的值。
- 在构建前决定路线：CREATE 固定为封面加 A4 纵向正文；横向、纯表单或表格页、不要封面，或页数上限放不下封面加正文时，直接走

- **`render_body.py`**：
  - `col_widths` 按总和归一化，相对宽度即可，无效输入时等宽；
  - 没有标题的图表只显示 “Figure N”。
- **封面**：
  - 六种封面的 meta / 标签行只连接非空部分；
